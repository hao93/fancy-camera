# Fancy Camera 3.0.6

- 相册顶部顺序调整为“全部照片 → 胶卷”；默认照片入口、选中状态和两个页面原有功能保留。
- 修复默认 EV=0 时的曝光一致性遗漏：过去只有非零 EV 或手动曝光转移才比对预览与拍照的实际快门、ISO、光圈和后 RAW 增益，普通自动拍摄可能跳过核对。现在 EV=0 同样核对，存在已验证差异时只修正该差异，相同曝光不重复补偿。
- EV=0 已收到真实曝光数据但尚未稳定时，采用现有最多 1 秒的收敛等待；已稳定的连续拍摄立即继续，缺失曝光数据不制造快门或 ISO。
- 拒绝时间戳倒退的曝光结果，避免延迟回调覆盖较新的取景曝光。
- 支持手动传感器请求的镜头，在普通同会话拍照时也继承已确认预览的快门、ISO 与可用增益；不再仅限分时镜头转移。避免只在新拍照模板中设置 AE_LOCK，却让系统重新选择输出曝光。不支持时保留自动曝光锁定或原路径，闪光拍摄不冻结环境曝光。
- 对开放手动后处理、曲线模式及对应请求键的相机，将与快门曝光快照配对的真实预览色调曲线用于拍照，减少预览与拍照模板各自选择映射曲线造成的明暗差异。检查逻辑与物理相机能力、曲线点数、端点、数值与单调性；缺失或不支持则保留原有快速映射。闪光拍摄及无对应自动曝光快照的手动模式不套用预览曲线。
- 曲线请求在构造阶段被拒绝时，重新构造不带曲线的原请求；驱动异步拒绝时沿用原来的拍摄错误恢复，并在本次运行中停用该镜头的曲线复用。旧捕获事务的回调不能污染新一张照片。曝光诊断会记录是否请求了曲线复用。

预览与 JPEG 原本共用胶片调色参数；本次修正相机输入阶段的曝光与色调衔接，不用固定提亮值掩盖差异，不修改已有照片、胶片配方、镜头选择或成片尺寸。

## 验证与边界

新增覆盖 EV=0 的正负曝光差、相同曝光、后 RAW 增益、闪光例外、曝光收敛与稳定连拍；曲线快照配对、主摄 / 物理请求、缺失能力、点数限制、损坏曲线及无元数据回退；相册页签顺序、选中态和回调。继续执行既有相机 / 归档 / 手势回归、GLSL、桌面 EGL 像素和 APK 原签名检查。

以上是代码与桌面检查，尚未取得 vivo X100 Ultra 在明亮、暗光、各焦段、不同固件色调处理下的预览 / 成片对比，不能宣称已确认所有场景亮度完全一致。驱动的局部色调映射也未必由公开曲线完整描述。
