# Fancy Camera 2.4.8 · 快速切镜试验与准确耗时诊断

版本 2.4.8 / versionCode 52，保留标准包名、原签名、底片和设置。

## 如何使用

设置 → 拍摄 → **快速切镜（实验）**。默认关闭，手动开启后保存选择。状态会显示待验证、使用中的逻辑相机 ID，或已回退及原因；失败后可点“重试快速切镜”。RAW 开启期间暂停实验，继续使用独立镜头，不会关闭 RAW。

## 根据实际诊断调整

用户提供的 2.4.7 日志显示三个独立镜头均能预览，切换没有发生兼容重试。最后一次超广角切主摄共 847ms：调度17ms、关闭旧设备182ms、准备和打开36ms、配置133ms、等待图像与结果466ms、绘制13ms。主要等待不是动画，也不是已验证路线缓存未命中。

本版尝试让同一逻辑相机会话承接变焦，减少关闭、打开和配置输出的次数。是否能使用及是否更快仍由手机固件实际输出决定。

## 实验路线

- 根据已发现的逻辑多摄及物理元数据选择候选，标准列表优先、扩展候选随后；不以 ID 数字猜测镜头。候选要求覆盖 14–230mm，PRIVATE 取景与 JPEG 尺寸不低于当前质量设置的光学基准，不自动降低清晰度。
- 通过 CONTROL_ZOOM_RATIO 在同一设备、同一会话更新变焦，最多保留一个待验证请求；快速滑动只替换最新目标，已验证画面真正绘制后继续提交，避免堆积旧变焦请求。
- 逐帧核对请求代次、倍率、活动物理 ID 与图像／结果时间戳。14–22.9mm 必须为超广角、23–84.9mm 必须为主摄、85–230mm 必须为长焦。旧画面、缺失信息或主摄高倍裁切都不能代替长焦验证。
- 系统已完成的变焦不再做第二次软件焦段裁切；原有画幅、方向、对焦坐标、曝光、胶片和镜头记录继续使用。API 33+ 显式使用传感器时间基准，API 34+ 关闭读取完成时间戳，使预览和 JPEG 能与曝光开始时间配对；低版本保持默认接口。
- 首次会话使用原有 8 秒首帧超时，使用中的单次变焦最多等 1.2 秒。首次候选失败尝试下一个；使用中失败恢复最新目标焦段的稳定路线，并按固件记录暂停原因，后续启动不反复重试。
- JPEG 也要与该次快门的已核验结果精确配对，之后才进入原有保存流程。超时或镜头不符不保存为成功照片，不自动重拍，提示用户等待稳定路线恢复后重拍。
- 拍摄中的 RAW、预览质量和实验模式变更延后到当前拍摄完成再应用；实验缓存、暂停记录与原有稳定路线缓存分开。

## 诊断与验证

切换起点改为最后实际绘制的镜头与焦段，另外记录上次请求，避免把快速滑动的请求值误当成之前实际显示的镜头。诊断补充请求提交、图像到达／处理完成、实际物理 ID，以及本次设备打开和会话创建次数。继续保留上一帧和短渐变，真实未就绪时不把动画当作实时预览。

完成 1200 项 Java 主机回归、9 套 GLSL 编译／链接、APK 原签名与对齐核验，覆盖真实输出门控、所有常用焦段和光学边界、反向滑动、过期回调、计时器、清晰度准入、候选回退、RAW、延后设置及 JPEG 保存门控，保留既有曝光、方向、连续拍摄、显影和图库检查。测试使用可控 Android 接口替身；完整输出随本地交付验证文件保存。

**未完成 vivo 真机验证**：尚不能确认当前固件允许该逻辑路线，也未测量新版在明亮、暗光、近距离和长焦文字场景下的耗时与细节。只有本机实际配对的帧才能通过运行时核验；主机接口替身不等于真机测试。不承诺已达到原生无感。

源码、版本标签及 Release 发布到 GitHub，附标准 APK、update.json、SHA256SUMS.txt，并核验公开下载；不通过 ADB 安装。
