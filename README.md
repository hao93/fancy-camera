# Fancy Camera · Android 2.2.1

以彩色暗房和机械相机为灵感的摄影应用，使用原生 Java、Camera2 和 OpenGL ES 2.0。拍摄与暗房离线运行，无第三方库、应用账号或广告；联网仅用于读取和下载 GitHub Release 更新。

## 2.2.1：主摄首帧与切镜黑屏修复

修复2.2.0 PRIVATE路径的首帧相互等待：此前预览未就绪时GL提前返回，没有读取SurfaceTexture，而就绪又需要之后的画面回调；画面早于拍摄结果时可能占满缓冲队列，让主摄持续黑屏。现在GL每次绘制都先执行latchExternalFrame，再决定画面是否就绪；帧回调只通知读取，不依赖元数据是否已经到达。实际读取和CaptureResult可按任意顺序完成，两者齐备后才放行预览。

GL读取结果在相机Handler上核对会话代次、SurfaceTexture身份、前台状态、设备及会话，再标记可用。换镜、重建EGL、暂停或拍摄专用会话的迟到回调被丢弃，读取异常走恢复流程。重新点击相同焦段时，如果设备仍未打开，会重新请求打开并触发绘制，不再直接返回。

PreviewHold隔离此前其他GL操作留下的错误，失败复制不丢弃同尺寸的上一张完整画面；首次缓存失败则清除分配尺寸，在下一帧重试。连续焦段、预设吸附、物理镜头边界和同镜头不重连均保留；跨物理镜头仍以最近完整画面等待新帧，不把缓存当作相机已就绪的证据。照片清晰度与镜头选择规则不降级。

780项Java回归通过，新增15项真实读取/就绪/绘制保护方法的受控检查，覆盖缓冲释放前无法返回结果的顺序、画面/结果各自先到、会话和纹理失效、后台回调、异常恢复、同焦段重试及GPU缓存失败恢复。四套原有GLSL、四套mediump兼容与保留帧程序编译/链接通过。主机接口替身不能证明vivo真机主摄已恢复或完全无黑屏，本次未安装或操作手机。详见[2.2.1 Release说明](releases/2.2.1.md)。版本2.2.1 / code34，保留原包名和签名，发布GitHub Release，不通过ADB安装。

PreviewHold在GL线程缓存最近完整渲染帧，等待新镜头、有效帧或覆盖目标裁切的YUV区域时，向每个交换缓冲重新绘制缓存，避免默认帧缓冲清空导致黑屏。GPU内复制，无CPU逐帧截图读回；同尺寸复用纹理，视口变化不拉伸旧画面，EGL重建重新开始，后台失效。YUV转换保留25%裁切余量，接受同代在途帧；只有ROI确实覆盖当前视野才复用。跨光学镜头仍需固件重新配置，等待期间会短暂停留上一帧；失败明确提示且不允许把缓存当作就绪画面拍摄。

## 1.18.1：消除预览颗粒的规则斜纹

移除放大正弦的伪随机公式，改为512×512单通道随机纹理；256级亮度各出现1024次，经固定种子的整数洗牌打散，均值为零，水平、垂直及斜向邻近相关度均低于0.005。每个EGL上下文只生成并上传一次256KB数据，按输出像素点采样，旋转、裁切不会把噪点拉成斜纹；暂停/恢复不逐帧生成或上传，不引入噪点闪烁。颗粒为零或胶片强度为零时绕过颗粒贡献。保留颗粒参数及所有配方、照片显影算法、收藏和镜头设置。

## 1.3.0：针对已发现长焦后的 Broken pipe

用户的实际 1.2.0 诊断已能读取逻辑 ID 2/5 及子镜头 0/3/4，识别 4 为约85mm长焦、3为约14mm超广角。两种包名均在逻辑2的物理输出配置处出现 Broken pipe，随后设备严重错误，继续尝试逻辑5也失败。这与上一份只有0/1的诊断是不同阶段的问题，不能再归因为没有检测到长焦或单纯缺少包名白名单。

本版修正以下实现问题，并提供尚待实机验证的输出兼容方案：

- 对实际返回、能识别的超广角/长焦物理ID，保留独立打开候选，优先尝试用户日志中已确认的3/4。能读元数据不代表能独立打开；失败后继续尝试原有逻辑绑定，不能改用主摄裁切。
- 副摄不再默认同时配置物理PRIVATE预览和大幅YUV照片。先尝试单路YUV取景，拍照时切换同一镜头的单路YUV拍摄会话，然后恢复取景。YUV取景通过单独的GPU采样路径显示，保留胶片与数字扩展裁切。
- 物理绑定输出只选逻辑/物理两端共同公布的尺寸；优先约640×480预览，失败后约320×240、较小拍照输出，最后尝试单路PRIVATE分时取景。实际尺寸来自设备，不强行设置未公布尺寸。较小预览不代表成片被固定为预览分辨率，照片尺寸独立选择。
- 配置前调用 isSessionConfigurationSupported；不支持的组合提前跳过，设备未实现该查询时才实际尝试。设备严重错误或配置异常后关闭并等待 onClosed，再打开下一方案；不在已损坏的同一连接上继续配置，也不让新镜头与尚在关闭的旧镜头争用相机。
- 物理输出的 CaptureRequest 使用带 physicalCameraIdSet 的创建接口，再设置该物理镜头支持的参数。原代码未传入集合就尝试设置物理请求参数，已修正。
- YUV预览必须同时收到捕获结果与图像数据才标为就绪；原始YUV单独处理传感器旋转，外部纹理保留原有方向处理。旧ImageReader回调不处理新拍摄。

本版共59项纯Java测试通过（42项原路由/图像测试，17项关闭重开与YUV方向测试），两个实际使用的GLSL程序均通过编译/链接验证。仍无本机型真机验证，不能宣称已经实测修复用户固件上的长焦。若全部路径失败，需依据新版逐方案日志继续定位。

依据：[RootEncoder开发者关于物理相机ID与较小分辨率的讨论](https://github.com/pedroSG94/RootEncoder/discussions/2056)、[Android CameraDevice关闭及物理请求接口](https://developer.android.com/reference/android/hardware/camera2/CameraDevice)、[Android多摄输出限制](https://source.android.com/docs/core/camera/multi-camera)。论坛中也有[X100 Ultra用户关于不同相机应用副摄表现不同的反馈](https://4pda.to/forum/index.php?showtopic=998555&st=1060)，但没有给出适用于本固件的可复现修复配方，未照搬其他机型的厂商私有模式值。

用户的 vivo V2366GA / Android 16 实际诊断仅返回 ID 0（后摄约 23mm）与 ID 1（前摄约 24mm），两者均非逻辑多摄、没有物理子镜头。因此 1.1.0 的灰色档位在该次诊断中表示没有发现镜头，不能描述为已经配置失败。

- 标准版在 vivo 缺少超广角或长焦时，追加读取 0–31 中尚未知的数字 ID 元数据。只读取，不自动逐个打开。每个 ID 的异常独立处理；只将实际返回、能按光学元数据识别的镜头加入候选。数字 ID 本身不决定镜头类型。这是有限范围的厂商兼容尝试，不是 Android 保证支持的枚举方式，也不会授予系统未开放的权限。
- 诊断区分“没有返回镜头”“已发现但未验证”“已经收到取景结果”“已发现但打开/输出失败”。取景结果不等于拍照已验证。
- 提供可选的独立兼容测试 M 包，安装标识为 com.meitu.meiyancamera，显示名称为“银盐暗房·镜头测试”。此方式依据 GCam 维护站的 vivo 包名兼容记录，目的为测试固件是否按应用标识过滤镜头。本包仍完全是本项目代码，不是美颜相机的产品，也不包含其代码、账号或服务。与标准版使用相同代码，只有安装标识及由其决定的显示文字不同。
- 如果手机已经安装美颜相机或占用同一标识的 GCam，兼容 M 包可能因签名冲突无法安装；保留现有应用，跳过此测试即可。兼容 M 包可以与银盐暗房标准版共存，但内部底片及设置不共享。无需也不要为此卸载现有应用。
- 两个包都未经 X100 Ultra 真机验证，不能将本版视为已经解锁副摄。若两者仍只返回 0/1，说明本次有限兼容尝试未建立三镜路径，需要进一步的固件接口资料或厂商开放支持。

纯 Java 测试增加了该用户诊断的回归用例，共 42 项通过；具体测试范围见附带说明。

## 本版：光学镜头优先

| 等效取景焦段 | 基础镜头 | 应用额外裁切 |
| --- | --- | --- |
| 14mm | 14mm 超广角 | 无 |
| 23mm | 23mm 主摄 | 无 |
| 35 / 50mm | 23mm 主摄 | 35/23、50/23 倍 |
| 85mm | 85mm 潜望长焦 | 无 |
| 135 / 230mm | 85mm 潜望长焦 | 135/85、230/85 倍 |

三颗后摄为离散的原生焦段，不是连续光学变焦。镜头规格以 [vivo 官网](https://www.vivo.com.cn/vivo/x100ultra/) 为依据。标签使用 X100 Ultra 标称等效焦距；接口元数据的估算值会有差异。

程序枚举公开的独立相机与逻辑相机下的物理镜头，按焦距和传感器尺寸识别镜头。优先独立 ID，其次使用 OutputConfiguration.setPhysicalCameraId，将预览和拍摄绑定同一物理镜头。物理镜头采用 YUV 拍照，先尝试预览和拍照并发输出，失败后尝试同一镜头分时输出。只有 23mm 主摄允许系统默认 1× 备用路径，并回读焦距、裁切区域和可获得的当前物理 ID 核验。

硬件变焦请求固定为 1×。35/50/135/230mm 在对应基础镜头图像上中心裁切，预览与保存使用同一倍率；裁切不插值放大。14/23/85mm 不增加应用数码变焦。常规输出尺寸、系统畸变校正和输出宽高比不属于此承诺范围。

若某颗基础镜头未公开或输出配置被系统拒绝，会禁用对应整组，并显示原因。85/135/230mm 不会退回主摄裁切。相机未就绪时不展示上一个镜头的旧画面。照片的底片记录保留镜头来源，底片详情可查看。

网上能查到硬件规格与部分第三方配置；没有查到适用于所有 OriginOS 固件的统一镜头 ID 表。[GCam 维护站](https://www.celsoazevedo.com/files/android/google-camera/troubleshooting/#package-name) 说明 vivo 等设备的辅助镜头开放可能受包名影响；[X100 Ultra 的配置作者](https://t.me/s/xmlshamimmod?before=1598) 发布过特定 GCam 版本配置。它们不能证明本应用在用户固件上具有同等访问能力。标准版保留 com.silverroom.camera 包名，兼容 M 包按上文使用另一标识；运行时发现和配置验证决定实际可用镜头。

## 使用

- 取景：选择胶片与焦段，点击画面对焦，长按请求AE/AF锁定，点击顶部锁定条×解除。点击 EV 数值打开曝光调节面板。点击白色圆形快门或音量键拍照。
- 胶片：左侧分类按钮快速切换收藏、原有分类与经典胶片、电影美学、现代调色、复古年代、特色摄影；滚轮滑动或点击实时应用。右侧三点打开51款完整胶片库，可分类、搜索、收藏和查看最近使用；选中胶片下方显示强度，再次点击已归位的选中项可调节完整胶片强度。胶片库底部或主分类菜单可进入收藏排序。名称为自定义灵感配方，不代表品牌官方模拟。
- 暗房：导入照片，调整 C / M / Y 滤色转盘、曝光、颗粒及褪色；按住“看原片”比较，点击“显影并保存”导出。
- 底片：查看、分享照片，或使用保留的底片再次显影。
- 闪光：关 / 自动 / 开，取决于当前镜头支持情况。定时为 3 秒或 10 秒。
- 镜头信息：长按顶部工具栏“画幅”按钮查看自动检测结果和失败原因，支持重新检测、复制诊断。
- 外观与升级：点击底部右侧设置图标，在“黑色 / 白色”中切换界面并自动保存；“启动时检查”控制自动检查，默认开启，可关闭；关闭后仍可手动“检查升级”。无新版或网络不可用时不弹窗。

面向 X100 Ultra 竖屏和长屏设计，处理状态栏、手势区域及挖孔安全区。最低 Android 11，目标 Android 15，纯 Java 字节码，可在 ARM64 安装。本版保留 1.0.1 的预览方向修复，避免重复叠加 SurfaceTexture 中的传感器旋转与前摄镜像。

## 保存与限制

成片为 JPEG，保存到系统相册 Pictures/Silverroom；可选的原生DNG也保存到该目录，内部副本可从详情导出。相机优先选择不超过约 1300 万像素的 4:3 常规拍照输出；显影最长边为 4096 像素，数码裁切后像素进一步减少。预览和成片采用同一色调参数，颗粒分布受分辨率影响。

底片与再次显影记录位于应用内部。覆盖升级保留数据；卸载会清除内部底片，已导出的系统相册照片保留。拍摄申请相机权限；照片导入使用系统照片选择器，不可用时调用系统图库。另声明联网与请求安装应用权限，仅用于GitHub升级；不申请广泛存储或相册读取权限。

没有 X100 Ultra 真机进行本版三镜会话、对焦、闪光、方向和保存验证。不能承诺所有固件开放全部镜头，也不保证原厂 V3+ 算法、2 亿像素模式或原厂相机画质。具体验证范围见随包验证说明。

## 构建与测试

按用户最新要求，后续新版默认推送源码并发布Release，不自动通过ADB安装到手机。标准版执行`build.ps1`完成签名验证后，依次执行回归测试和`publish.ps1`。发布使用本地GitHub CLI登录账号；不上传签名私钥或ADB配置。发布失败会保留APK并明确报错，不能将构建成功视为发布成功。只构建使用`build.ps1 -SkipPublish`；旧参数`-SkipInstall`保留兼容，仅明确提供`-Install`且未提供`-SkipInstall`时才调用安装脚本。M兼容版不自动发布或安装。

`install.ps1`验证APK包名/原签名和本地配置中已配对手机的序列号/型号，再执行`adb install -r --no-incremental`，并回读安装版本。无线连接失败会保留APK并明确提示安装未确认，不能将构建完成当作安装成功。配置在相邻`adb-state/device.json`，设备地址变化时更新该文件；同目录配对密钥不得打入源码包。单独验证连接而不安装：`install.ps1 -Apk <APK路径> -VerifyOnly`。

Windows、JDK 17+、Android SDK Platform 35、Build Tools 35.0.0；设置 JAVA_HOME 与 ANDROID_HOME。运行 build.ps1 -Variant standard，输出 build/standard/Silverroom-2.2.1.apk。运行 build.ps1 -Variant compat-m，输出 build/compat-m/Silverroom-2.2.1.apk。构建只在对应 build 目录写入派生 Manifest，不修改源码 Manifest。两种包使用同一 Java 源码。原签名密钥及密码从本地相邻`adb-state/signing.json`读取，也可通过`FANCY_CAMERA_KEYSTORE`和`FANCY_CAMERA_KEYSTORE_PASSWORD`环境变量提供；缺失时构建失败，不生成替代密钥。只有同一标识且同一密钥签名才能覆盖既有安装。源码包不包含签名私钥、密码、SDK 或完整 JDK。

每次发布先递增Manifest的versionCode及versionName，编写`releases/<版本>.md`，然后执行默认标准构建。`publish.ps1`只提交源文件白名单，拒绝私钥/构建产物/配对状态，推送main与`v<版本>`标签，生成标准APK、更新清单及校验值。上传草稿后读取GitHub返回的资源大小和digest逐一核验，通过才公开Release。已公开版本不覆盖、标签不强推；有变化应增加版本。仓库配置位于`release.json`，App内固定更新源位于`UpdatePolicy.java`，两处必须一致。

运行 test.ps1 执行纯 Java 的镜头路由、相机关闭重开及 YUV 数据/方向测试。提供 -ShaderValidator 指向 glslangValidator.exe 可额外验证实际GLSL着色器程序。测试不需要手机，但不能验证厂商实际相机输出行为。
